# change-gate lite（发布前三道门 · 精简版）

> 完整版含六道门与脚本校验，本精简版覆盖个人发布/交付最常用的前三道。

## gate-00 intake（受理）

发布/交付前回答四问，写进 gate-log：

- 这次变更是什么（一句话）
- 范围内 / 范围外各是什么（范围外登记候选清单，不顺手做）
- 有没有触碰红线（诱导生产环境 / 客户隐私未脱敏 / 冒充主体）→ 有则停
- 变更类型（代码 / 运营发布 / 文档）

## gate-01 fact-baseline（事实基线）

- 列出本次依赖的关键事实，每条标注来源与证据分级（✅ 实测 / 🟡 需复访）
- 🟡 项必须写明「何时、如何关闭」；无证据的事实不进决策

## gate-02 decision-table（决策表）

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| （本次要拍板的每个点一行） | 结论 | 证据编号/来源 |

规则：依据是 🟡 的结论不得作为不可逆动作（对外发布、收费、删数据）的唯一依据。

## gate-log 模板

```markdown
# GATE Log: <变更名>
- 变更 ID / 日期:
- gate-00: PASSED / BLOCKED（理由）
- gate-01: 关键事实 + 待关闭缺口
- gate-02: 决策表
- 执行记录:（每完成一步追加一行，含日期）
```

## 使用场景

- 发布一篇对外内容前（红线自查放 gate-00）
- 给客户交付 MCP 封装前（验收报告对账放 gate-01）
- 定价/承诺前（决策表放 gate-02）
